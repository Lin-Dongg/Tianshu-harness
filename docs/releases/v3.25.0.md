## 会话分叉（fork）——交互闭环

分叉一条链路的四个方向全部补齐，此前「fork 之后怎么返回主会话」只能靠侧栏凭标题找：

- **创建三入口**：工作区 header「分叉会话」钮、消息右键「从此点分叉」（锚定该条所在 user 轮）、**assistant 消息 hover 动作行**新增的显性 ↪ 钮（与右键同一回调，不再藏在右键菜单里）。
- **子回父三通道**：子会话时间线血缘 chip 变为可点（带「返回源会话」动作文案）；header 常驻「源会话」返回钮（源会话归档/删除自动隐藏）；**侧栏会话行新增 ↪ 血缘角标**——tooltip 指认源会话标题，可点击直跳。
- **父跳子**：父会话 header 新增「N 个分叉」下拉（新的在前），点击直达任一子会话。
- **兄弟互跳**：子会话有同源兄弟时，header 出「N 个同源分叉」下拉（源会话置顶 ↩ 标记），不再经源会话中转。
- **顺手两修**：`ForkDialog` 落点改主次结构——「分叉到当前工作区」主推成 accent 底默认路径，worktree 两个落点收进「高级选项」折叠；**折叠项目分组不再误清当前会话**（`setProject` 同项目幂等，此前点当前项目分组头会把正在看的会话从工作区静默清掉）。
- 复审跟进：血缘角标点击补 `setSurface('workspace')`（非 workspace 页面点角标原先静默换会话而视图不动）。

## 侧边栏文档预览（word / pdf / pptx / 图片）

此前在文件树里点开 `.pdf/.docx` 是一屏 utf-8 乱码：

- **PDF** 用 pdf.js canvas 渲染（翻页 / 缩放 / 页码指示，高分屏清晰）——不走路径被 CSP 挡的 iframe。
- **DOCX** 用 mammoth 转 HTML + 白名单消毒后渲染，内嵌图片保留，链接点击走系统浏览器。
- **PPTX** 由 sidecar 调 LibreOffice headless 转 PDF 后复用 PDF 预览（转换结果按 mtime+size 缓存）；**未装 LibreOffice 时优雅降级**为提示 + 「在系统中打开」，不再装死。
- 图片文件（png/jpg/gif/webp/svg）同路修复乱码。单文件 8MB 上限（对齐附件口径），超限给「系统打开」出口。ThreadView 的文件抽屉与文件树共用同一套预览组件；pdf.js/mammoth 走懒加载独立 chunk，不进首屏。

## Composer 输入框

- **busy + 空输入时提交键变停止键**（ChatGPT 对齐）：没有内容可发时不存在「想发却点成停」的误触；有内容时仍为排队发送。Esc 打断保留为键盘路径。
- **切换会话保留附件草稿**：图片/文档附件此前是会话组件本地 state，切会话即丢（文字草稿早有会话级暂存）。补齐同机制——切换回来附件还在；发送成功/手动删光自动清条目。附件只进内存不落盘（base64 体积大，防 localStorage 配额）；发送失败回填的 token 消费改幂等，顺带修了 dev StrictMode 下附件回填翻倍。
- **queue lane 决策钉点**：「立即引导 / 撤回」固定在 composer 上方悬浮条。
- **键位提示按平台渲染四连**：⌘ 硬编码清零，界面键位、命令面板标题、工具条与终端提示全部按平台注入（issue #246）。

## 供应商与模型

- **增删正确性四修**（桌面供应商审计落地）：
  - **CJK/特殊字符名供应商的 key-pool 六条路由全 404**——服务端漏 `decodeRouteParam`、客户端漏 `encodeURIComponent`，两侧对齐后中文名供应商的 key 增删/模型编辑恢复正常（回归测试钉死）。
  - **删除供应商不再留孤儿密钥、同名重建不再复活旧凭据**——keys 池槽位（`名称:keyId`）的 secret 此前整批漏删；池文件只在非空时写，最后一个带池供应商被删时旧池残留复活。改为全槽位引用扫描回收 + 池文件存在即重写。
  - **删除默认 key 不再让供应商半死**——默认 key 的凭据就是顶层槽位，直接删会让状态面板显示「未配置」、默认供应商场景下次快照重建直接抛错。现在剩余 key 的凭据自动提升到顶层槽（复审跟进再把提升不变量从「按 default id」推广为「被删 key 的凭据正是顶层槽所指」并补齐 env 对称面——被提升的 key 日后再删不再留僵尸凭据）。
  - **key 池写操作接入配置热更**——新增/轮换 key 立即对存活 agent 生效，不再等下一次 provider 级写入。
- **新增阶跃星辰 StepFun 预设**（step-5-preview，规格与定价取自官方文档）。
- **「测试模型调用」结果落成持久框**——模型名 + 三色状态点（对话通过 / 仅连通 / 失败），不再只有几秒自毁的 toast。
- **生图模型注册成功给可见反馈**（右上角绿字提醒）。
- **请求体上限 `provider.maxBodyBytes` 可配置**（issue #251 后续：护栏默认关闭，超限文案的「最大来源」不再失真）；错误分类器不再把裸三位数字（如缺 npm script 的输出）误诊成「临时 API 错误」。
- **TLS 中间人判定改证据驱动**——`tls_intercept` 按本机探测结果分支：检出中间人 ⇒ 确定性失败零重试并给本地处置；未检出 ⇒ 更可能是服务端证书链半更新，留 1 次重试，不再把用户引去瞎调杀毒软件。
- **用量口径两修**：`turn_complete` 累计快照改「末值」口径（中断补发 usage + 实时 contextTokens）；输入框缓存命中率显示不再一个 run 冻一次，分母改内核口径。

## 安全与护栏

- **授权/改档「卡住」三处根修**：免审批档改档时挂起的审批此前原地等待像卡死——新增 `approveAllPending`（对偶 rejectAllPending），per-session 切换与全局广播两条路径对免审批档放行挂起审批；非免审批档不追认。附 maxTurns 联动全量收口与档位诚实化。
- **Windows 代码签名管线落地（fail-closed）**：Tauri 不读旧的 `WINDOWS_CERTIFICATE*`（electron-builder 约定）——「配了证书」与「没配」产物一样而流水线全绿，这是安装被杀毒软件拦的主因。改为 `signCommand` → 包装脚本：有签名命令就签，没有必须显式 `TIANSHU_ALLOW_UNSIGNED=1` 否则构建失败；CI 走 Azure Artifact Signing（0.11.0 定版）；**新增验签闸门**逐产物断言 `Status=Valid` + 有签名者 + 有时间戳（无时间戳的签名在证书过期当天全部失效），产物零匹配也判失败不做假闸门。
- **TLS 中间人可诊断**：新错误类别 `tls_intercept`、`/doctor`「HTTPS 信任链」、桌面 `GET /environment` 的 `tlsTrust` 字段（系统 CA 是否并入生效链 + 已知中间人根证书扫描——undici 只报 fetch failed，证书原因埋在 cause 链里）。
- `update.ps1` 启动去掉 `-WindowStyle Hidden`（降低主防敏感形状）。
- **prev-session-handoff 注入改为显式默认关闭**（并行会话安全）：跨会话注入闸门解耦，默认不再自动注入上一会话的交接文档，需要时 `RIVET_PREV_HANDOFF=1` 开启；同步启用「peer 编辑后读缓存失效」。

## 已知问题

- **Windows 杀毒软件误拦/误杀族（卡巴斯基等）**——三类现象成因与处置不同，请对号：
  1. **安装被拦**：SmartScreen「Windows 保护了你的电脑」、卡巴斯基报「未知发布者」或直接拦截——主因是 **Windows 产物当前仍未签名**（签名管线本版已落地，**证书采购与厂商白名单进行中**，签上之前此现象仍在）。处置：点「更多信息 → 仍要运行」；企业策略禁止运行时联系 IT 加白。
  2. **主防「误杀」**：安装器/更新脚本被卡巴斯基主动防御拦下（表现为「点了没反应」）——安装器在 TEMP 落 PowerShell + 枚举进程强杀（为解决 node.exe 文件锁，属正当理由但形状撞主防启发式）。处置：把安装目录与 `%TEMP%\tianshu-*.ps1` 加入杀毒软件白名单，或临时暂停主防后重装。**我们正在走 Kaspersky Allowlist Program 与 Microsoft Defender 误报提交流程（每版提交）。**
  3. **会话内 443 不通**（`UNABLE_TO_VERIFY_LEAF_SIGNATURE` / `SELF_SIGNED_CERT_IN_CHAIN`）：卡巴斯基「加密连接扫描」把自签根证书装进系统存储做 TLS 中间人——sidecar 默认只信内置 CA 列表。**这不是服务端故障**。处置（三选一）：卡巴斯基设置里把天枢的 API 域名加入「加密连接扫描」排除项；或暂停「加密连接扫描」；或以 Node `--use-system-ca` 让 sidecar 信任系统存储。本版起 `/doctor`「HTTPS 信任链」与桌面环境接口可直接查出是不是中间人，`tls_intercept` 报错会给对应处置指引。
  - 完整问题档案：`docs/known-issues/2026-09-23-windows-antivirus-interception.md`；用户侧四类处置：`docs/guides/troubleshooting.md` 第 11 节。另注意：安装器会结束「集成终端里正在运行的 node/npx/tsx」以释放文件锁——那不是杀毒软件，属预期行为（见 2026-09-10 file-lock 档案）。
- **macOS 首次打开报「已损坏」**：本版 macOS 包仍为 ad-hoc 签名、未经 Apple 公证（Developer ID 证书未就位）。安装后执行一次 `xattr -cr /Applications/Tianshu.app` 即可；应用内自动更新不受影响。
- **MiniMax-M3 视觉上游故障（延续）**：MiniMax 服务端对 M3 图片请求返回 500（纯文本正常）——M3 作识图桥暂不可用，建议 glm-4v-flash / deepseek-flash。
- **手机遥控为局域网设计**：无 HTTPS——令牌是 LAN 唯一凭证，公网请走 Tailscale / SSH 隧道，不要直接端口映射。
- **结构棘轮存量**：`max-lines` 守卫当前仍有若干条并行会话在途增长的超限欠账（非本版内容引入），归各自会话收口。
