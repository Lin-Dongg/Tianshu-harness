## 主题：Team 模式全线打通 + 桌面端精致化三波 + 语音输入重构 + 交付不自动提交

v2.25 是 v3.0 前的最后一个 2.x 版本。Team 编排入口在之前版本中被四个 P0 缺陷堵死，
本版全部修复。桌面端完成三波 UI 精致化，首屏瘦身至 2.5MB。语音输入从体验重构到
精度优化。新增交付不自动提交开关，让用户可以完全控制提交节奏。

---

### 1. Team 编排模式全线打通（4 × P0 修复）

v2.24.x 的 team 编排入口被四个配置层缺陷堵死在一切默认配置下不可达：

- **`team_orchestrate` 不可见**：原在 EXTENDED 工具层被 deny-list 门控摘除，主控看不到。
  修复：升入 CORE 工具层（内核预算 27→28），同步从 tool-preset minimal-excludes 移除。
- **`plan_task` execute 路径必然超时**：默认 120s，不足以跑完多 worker 派发 + 门禁 + 审查。
  修复：`execute:true` 时对齐 `team_orchestrate` 的 600s。
- **新建文件类 patcher 全灭**：`materializeScope` 把 scope 文件不存在当作致命错误，
  worker 被 blocked——但新建文件任务 scope 文件本来就不存在。修复：新增 `toBeCreated`
  语义，合法路径但文件尚不存在时不 block，仅标记为待创建。
- **项目级 `.rivet-config.json` 对 sidecar/桌面端静默失效**：`resolveServeContext`
  调 `loadConfig()` 不带 cwd 参数，桌面端会话永远吃不到项目级 agent 配置。
  修复：per-session 按 cwd 合并项目级 agent 段。

### 2. 桌面端精致化（Wave 1–3）

三波 UI 与性能优化，全面改善桌面端体验：

- **Wave 1 — 布局基准化**：窗口尺寸比例化 + 三栏像素基准 + UI 缩放支持
- **Wave 2 — 首屏瘦身**：首屏关键路径 2.9MB → 2.53MB，highlight.js + KaTeX
  移出首屏，vendor 拆分，eager bundle 3021 → 2532 kB
- **Wave 3 — 按需加载**：i18n 按语言拆包、覆盖层懒加载、vendor-ui 拆分、
  设置分组页各自成 chunk——点击不再撞上空白

### 3. 浏览器面板完善

- 浏览器面板从"可 undock"改为「就地看图 + 可 undock」，自动弹右栏退场
- `browser_debug` 新增 `act` / `extract` / `observe` 三个自然语言原语（启发式元素定位）
- 浏览器面板自动展开不再把历史截图误判为新增
- 补上此前未完成的浏览器面板渲染入口接线

### 4. 语音输入体验重构

两个 bug 修复 + 两个精度优化：

- **修复**：长句子识别时前段被覆盖——`recognition.onresult` 闭包捕获 stale `text`，
  每个 interim 事件都从同一基值拼接（React 闭包陷阱），改为 `useRef` 累积器
- **修复**：语音引擎返回错误码时 toast 提示不显示具体原因——补上 `speechError` 状态映射
- **优化**：`maxAlternatives = 3`——请求引擎返回多个候选结果，浏览器支持时可从中选最优
- **优化**：`SpeechRecognitionPhrase` 上下文偏置（Chrome 120+）——向引擎注入 40 个编程
  术语偏置（React hooks、TypeScript 关键字、常见 dev 词汇），大幅减少
  "useState → use state"、"async await → a sync await" 类误识别

### 5. 交付不自动提交开关

新增 `agent.delivery.autoCommit` 配置项（默认 `true`，向后兼容）。设为 `false` 后，
agent 完成任务时仍运行完整交付门禁和审查报告，但 `git commit` 不实际执行——
用户审查 diff 后手动提交。

全链路落地：Zod schema → config manager → deliver-task 门控 → bootstrap 注入 →
REST API → desktop client → Settings UI toggle → 中英文 i18n。

### 6. TUI 增强

- **`/config` 设置面板**：子代理路由 / 审查 / 识图三块 TUI 空白收进一个面板，
  不再需要盲改 `config.json`
- **审批等待可观测化**：spinner 显示「等待审批 \<tool\> · Ns」，不再静默等待
- **日志落点入口**：`rivet logs` / `/logs` / 桌面端打开日志目录，log 诊断可触达
- **domain picker 叠影修复**（hotfix from v2.24.3）
- **诊断态停滞门槛右移一档**：W3 收敛文案不再是死码，收敛探测器不再被静音

### 7. 工具链稳定性

- `run_tests`：filter 修复 + 未定位文件改为 fail-loud（不再静默返回 0 passed）
- `edit_file`：正则匹配失败改为诊断提示，不再事前拦截含正则字面量的编辑
- `ast-grep` / `grep`：裸 catch 修复——「未安装」已被证实是错误归因，真实加载失败不再被吞
- `hash_edit` / `edit_file`：锚点失效的成因说明 + 布尔入参归一
- path-grants：第三方依赖缓存目录默认 read 授权，根治 `read_file` 在 node_modules 卡死
- `read_file`：依赖缓存目录自动 read 授权

### 8. 性能与基础设施

- **会话历史尾部读截断**：截断挪进 worker，不再把丢弃的九成搬过线程边界
- **review prompt 压缩**：禁 auto 重试——缓解 flash 审查全灭
- **prompt appendix 部间双空行缩为单空行**：去无意义 token 浪费
- **测试 runner 收编**：4 个 orphan 测试脚本恢复执行
- **测试挂死防护**：超时上限 + 中断带走子进程 + tsc 只跑一遍
- **覆盖层空闲预热**：设置分组页各自成 chunk

### 9. 诊断与遥测

- Sensorium 四阈值死路由清理 + pressureRelative 超基线幅度修复
- 六维阈值覆盖探针 + 遥测探针共享层
- 第二轮指标监测——闭第一轮留下的三条待数据闭环
