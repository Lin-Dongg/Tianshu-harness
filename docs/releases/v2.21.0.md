### 1. macOS 自动更新签名错配根治（本版核心修复）

**问题**：v2.19.7 / v2.20.0 / v2.20.1 三个版本的 macOS 自动更新全部失效——用户从 v2.19.6 升级会被 updater 拒绝安装。Windows 不受影响。

**根因**（用同款 `minisign-verify` crate 逐包验签坐实）：`scripts/build-macos-release.sh` 构建前不清理 bundle 目录，Tauri 增量打包重打 `.app.tar.gz` 却不覆盖已存在的 `.sig`，导致三个版本沿用 v2.19.6（7/19）的陈旧签名。包变了、签名三天没动，minisign 验签必失败。

**修复**（bc2720bd / 928a359f / 2a57512f，对齐 `build-windows-release.sh` 已验证范式）：
- 构建腿前清理 `bundle/macos` + `bundle/dmg`，杜绝陈旧 `.sig` 残留（根治）
- `collect_arch` 加签名新鲜度闸门：`.sig` mtime 必须 ≥ tarball，否则报错退出
- 删除无签名兜底 tar 路径，缺签名直接报错
- `latest.json` 加签名时间戳校验：signature timestamp >60min 则拦截
- 导出空密码 env（构建实测发现：`~/.tauri/tianshu.key` 是加密格式但空密码，非交互环境读不到密码会导致签名静默失败）
- 构建后恢复宿主架构 node runtime（x64 腿会 prune 掉 arm64 runtime，坑到 dev 启动）
- 新增 `--arch` 单架构构建模式，规避双架构串行超时被 kill

**验证**：双架构实构建，minisign-verify crate 验签 arm64 ✅ + x86_64 ✅ 通过。

## 升级提示

### macOS 用户

**v2.19.7 / v2.20.0 / v2.20.1 用户**：由于之前版本的 macOS 自动更新签名失效，**请手动下载 v2.21.0 的 DMG 安装一次**，之后自动更新即可恢复正常。

下载后首次打开如提示「已损坏」（未公证），执行：
```bash
xattr -cr /Applications/Tianshu.app
```

### CLI 用户

```bash
npm install -g tianshu-tui@2.21.0
```
或在 rivet 内执行 `/update`。

### Windows 用户

自动更新一直正常，直接通过应用内更新即可。
