## 1. Starflow Iteration IV — From "can finish a run" to "can afford to iterate"

A post-mortem after the first real run (`.rivet/knowledge/starflow-retro-2026-08-03.md`) drove four mechanism upgrades, all shipped:

**A. Seat selection freedom**: `starflow` gains a `seats` parameter (mirroring `council_convene`), passed through both the first round and the review round. On revision re-submission, only "seats that rejected last round + relevant domain seats" are recalled instead of full review by default — cost drops immediately, rejection blocking power unchanged.

**B. Incremental review**: `draftItems` supports `revision` / `previousVerdict` markers. Items that passed last round and are unchanged are annotated "carries forward prior approval" in review rendering; council needs zero changes (rendering text is the contract). Guard: `revision` + `previousVerdict` co-occurring means "revised, re-review" —宁可 re-review than miss.

**C. Baseline pre-check**: Before the first council round, a working-tree state block is auto-injected (target files' git status hit lines + last 5 commits + must-answer sentence). "Already merged / already in tree" type rejections move from round 2-3 to round 1, no longer burning seats. Non-git environments degrade gracefully without blocking.

**D. Blocked attribution**: When a team wave has workers that didn't pass, the report appends a working-tree attribution segment — git status filtered to this wave's changedFiles; shared worktree with no diff artifact degrades to full listing annotated "cannot attribute per-file, do not `add` the whole directory". Under multi-session shared workspaces, directory-level hits are explicitly marked "may contain other sessions' changes". Eliminates the "concurrent session vs own worker" cognitive fog.

### Companion fixes

- `council` seat risk missing `mitigation` field broke `extractObligations` (root cause of starflow ignition failure) — entry normalization + consumer-side defense + seat prompt補 risk schema (root fix)
- `quotePath=false`: Chinese / non-ASCII paths no longer under-report in attribution segments and pre-check blocks

## 2. Collaboration Execution Reliability — Global Concurrency Gate and Its Review Fixes

P1-6/7/8 shipped a **global worker concurrency semaphore** (`agent.maxWorkers` or `RIVET_MAX_WORKERS`, default 3; top-level delegate/batch/background all enter the gate), explicit abortSignal parameterization (per-wave mailbox, no more read/write of shared instance state), and write-worker scope enforcement + cross-wave file conflict detection. Subsequent review fixed four real defects:

- **Nested delegation self-deadlock**: planner holds a slot waiting for child work, child waits for a slot — nested delegation (depth ≥ 2) is now exempt from the global semaphore; `RIVET_MAX_WORKERS=1` planner dispatch no longer inevitably deadlocks
- **Cross-wave conflict TOCTOU**: check-register moved into the same synchronous block; two same-file write-workers in the same tick can no longer both bypass
- **Zombie wake-up**: while waiting for a slot it now responds to parentSignal; abort dequeues and rejects; `delegate_task` main path passes signal through (previously the closure dropped it; the abort guard was dead code)
- **Gate scope**: verifier with empty scope running full tests is exempt; objective-gate over-reach judgment exempts test files; galaxy write-dimension with all files stolen explicitly skips and merges into report

## 3. Review Contract Overhaul — polarity + verdict ≠ status

Fixes the systematic distortion of "review verdict treated as worker failure" (a three-strike false escalation incident in one night):

- `ReviewFinding` gains `polarity: defect | confirmation` — blocking judgment only counts defects; confirmatory conclusions (code-read confirmation / link closure) go into a "verified list", no longer marked CRITICAL blocking
- `normalizeReviewVerdictStatus`: conclusive failed/escalated of review/verification orders (has findings and no infra-failure markers) normalize to passed — consecutive-failure counters, circuit breakers, escalation only record real runtime failures; review findings are no longer dropped
- Review instructions補 severity/polarity/status triple semantic contract; verified copy carries "N items verified confirmed"

**Worker contract hardening**: summary overwriting acceptance adds a status gate (passed result no longer overturned by a failed extension round); worker P0 hotfix pack (contract/liveness/concurrency four-fix + infinite-loop empirical regression lock).

## 7. Evidence Firewall Phase 2 — deliver hard gate

When deliver text references scout/worker assertions not independently verified, it upgrades from soft reminder to gate: `agent.scoutEvidenceFirewall = true` or `RIVET_SCOUT_FIREWALL=1` enables commit hard-block (opt-in, off by default); report-round warning always on. claim tracker wired through the full chain (hook callback + verifiedAt mark); `[pending verification]` annotation is the honest degradation path.

**cancel-rest short-circuit**: `first_success`/`quorum` aggregation strategies cancel remaining sibling workers once the target is met mid-way, saving tokens and wall-clock (`RIVET_CANCEL_REST=0` to disable); write-workers are never policy-cancelled (no half-modified files left).
