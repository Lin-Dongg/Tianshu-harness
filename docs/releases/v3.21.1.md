# v3.21.1 发布记录

> 日期：2026-09-16
> 上一版本：v3.21.0（2026-09-16 提交；npm 侧未见生效，本次发布包含其全部内容）
> 性质：**性能版 + 体验修复**——CLI 启动路径重写（launcher 入口 + V8 编译缓存 + TTY 前子命令快速路由）、会话工作区体系（issue #147）验收面收口、会话列表顺序稳定化。

## 性能：CLI 启动路径重写

审计实测 `node dist/main.js --version` 要 CPU(user+sys) 1.0~1.2s、RSS 117MB，而 `node -e ""` 基线仅 0.08s / 43MB；`dist/main.js` 的静态 import 闭包达 114/124 个 chunk、8.3MB JS。根因是 ESM 语义——`main.ts` 顶部 87 个静态 import、`bootstrap.ts` 119 个先于 `--version/--help` 与子命令路由执行。桌面 sidecar 早已由 Rust 注入 `NODE_COMPILE_CACHE`（实测 −35%），CLI 侧是明确缺口。

| 层 | 改动 |
|---|---|
| 新入口 | `src/cli/entry.ts`：在任何重模块动态加载前启用 `<RIVET_HOME>/cli/compile-cache`（不可写退 Node 临时目录，全失败 fail-open；Node <22.8 静默跳过） |
| 早路由 | `--help/--version` 由 launcher 直接从叶子事实源（`cli/help-text.ts` / `cli/version.ts`）输出，不再加载 main 图；`cli/early-routing.ts` 承接 `--profile/--trust/--untrust` 与 `config` / `provider` / `serve` / `sessions` / `--list` / `browser` / `logs` / `web` 路由，`main.ts` 调同一函数保证两条入口行为逐字一致 |
| 发布接线 | `bin.rivet` → `dist/cli/entry.js`（`dist/main.js` 保留兼容）、tsup entry、runtime bundle 的 shim 与存在性检查同步 |
| 桌面 sidecar | 入口切 launcher（`runtime_entry_path` 带 main.js 回退，旧安装包升级不炸）；ESM 声明落 runtime 根，否则 launcher 动态 import 的 main.js 会掉回无声明目录 |

实测（本机 macOS arm64 / Node 24.18.0）：

| 路径 | 前 | 后 |
|---|---|---|
| `--version` | wall 0.39~0.49s，CPU 0.43~0.54 | **wall 0.06~0.12s，CPU 0.08~0.09** |
| `--list` | CPU 0.66~0.79 | **CPU 0.09~0.10** |
| 重路径冷启动 | CPU 0.56~0.90 | 冷 0.59~0.68；warm 0.33~0.55 |

## 体验：会话工作区体系收口（issue #147）

v3.21.0 交付了默认工作区与临时会话隔离目录的能力，本版把验收面上缺的几格补齐：

- **来源徽标（持久呈现）**：`explicit`（用户自己选的目录）与未标注来源不挂标记——常态不占注意力；`临时会话` / `默认工作区` / `启动目录` 三态各带语义色与解释，落点在侧栏会话行（含折叠预览行）与会话内 Composer 动作行。
- **临时会话在侧栏有固定分组**：此前隔离目录的会话被项目派生过滤后在侧栏彻底不可见，现在有独立分组（不出现在项目名序里），且不暴露重命名/移除等项目语义操作。
- **隔离根可配置、可清理**：设置页新增「临时会话」卡片（占用一览、单删/批删、使用中的目录禁删），工作区面板可改隔离根——两个字段独立提交，清一个不会连带清掉另一个。
- **欢迎页快捷对话接入工作区意图**：此前该入口不带 `workspaceMode`，用户配置的默认工作区对它完全不生效，且静默落到应用启动目录；现在按「默认工作区优先 → 未配置落临时会话目录」判定，并在输入框下方常驻落点提示。

## 修复：会话列表不再随活跃上下跳动

排序键原先跟着活跃走（会话按 `updatedAt`、项目分组按 `lastActivity`），而列表每 2s 重拉一次——只要有会话在跑，行就持续滑动，点击落点会在指针底下让位；活跃会话所在分组还会上浮，分组之间互相串位。现在两层的键都不随活跃变化：组内按创建时间倒序、分组按项目名，时间分组 header 的桶与排序键同源（混用会让「今天」桶重复出现）。「最近项目」推荐位仍按活跃排序（那是推荐而不是列表顺序）。

## 内部

- **observerShadow 影子通道拆除**：20 个文件删除 + 16 文件精确编辑。该能力从未上线，且 v3.21.0 曾把它的默认值误设为随发行版生效——本版把能力与痕迹一并摘除（未上线能力的正确默认是「不存在」）。
- 发版 runbook 补两条实证坑（`gh release --latest=false` 必带；`npm publish` 成功后 registry 可见性有延迟）。

## 升级说明

- npm 包入口改为 `dist/cli/entry.js`（launcher）。`rivet` 的命令与参数行为不变，`dist/main.js` 保留兼容（`RIVET_SIDECAR_ENTRY` override 仍可用）。
- 首次运行会在 `<RIVET_HOME>/cli/compile-cache` 建立约 2.6MB 的 V8 编译缓存，按内容哈希自动失效，无需手工清理。
- Windows 桌面端已于 2026-09-16 补发（v3.20.0 以来的全部桌面改动随包，含 DeepSeek 登录白屏修复）；Linux 桌面未随发，`latest.json` 的 linux 条目待该平台上架后恢复。
