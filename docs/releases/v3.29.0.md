## 1. 多会话文件认领

- **冲突先问，不再直接拒**（`eefa3d7b7`）：对方活会话占着 exclusive claim 时，写前守卫改走审批「是否接管」。同意则释放对方认领再写入；拒绝或无人可答（headless）仍阻断。此前唯一出路是杀掉持有方进程
- **文件级租约**（`5c7b98d33`、`37262a72b`）：`claims.last_touched_at` 记录持有方上次写该文件的时刻，判定在 `claim-liveness.ts`。进程已死、或独占认领超过 10 分钟未再碰且该路径工作区干净 → 自动接管并在工具结果里写明判据；路径仍脏、或认领仍新鲜 → 继续问。心跳只说明进程还活着，不再当成「还在改这个文件」

## 2. 交付门与验证

- **项目外写入不再毒化指纹**（`4251eea67`）：往 `/tmp` 或兄弟目录写 fixture 曾让本会话全部验证被判 stale、交付门结构性 RED。路径分成项目内 / 项目外 / 敏感；项目外跳过，敏感路径仍 fail-closed
- **别人的全量失败不再硬 RED**（`4146b08d5`）：失败无法归因到本会话（`unattributed_failure`）或外部阻塞（`external_blocked`）降为 YELLOW，仍逐条列出失败测试。本会话自己的回归（`owned_failure`）继续硬 RED。无证据的覆盖义务不放宽
- **禁止用全量重跑凑绿**（`ac4addc0a`）：超时或 blocked 时用交付门点名的分批命令或 scoped；「点名文件隔离单跑全绿」即外部阻塞，不是你的 RED。门能跑但被影响面覆盖义务卡死时，也放行 scoped commit
- **非 git 工作区**（`671a697d9`、`c8c3f2fed`，issue #369）：本会话写过的文件不再误判成 co-owned；基线建不起来时报 YELLOW 并说明无法提交，文件改动仍生效，不再 GREEN「就绪可交付」
- **验证台账与反馈**（`4eece2896`、`f10fe80d2`、`493e0c971`、`364ba95aa`、`fb94b14c3`、`981afffe7`、`9a471915c`、`e26b213f4`）：纯查询（`wc`、`ls`、引号里的 `npm test`）不再记成验证；复合命令被拦时给出可粘贴的单条命令；bash 改过、快照没带上的 dirty 文件会点名；Node 测试完成证据按真实 runner 记账；义务从新鲜的依赖路径推导。阶段 A（隔离）失败后不再跑阶段 B（`cd2123008`）
- **基线不完整时不提交**（收编 PR #371，`04337b38d`）：只允许台账有证据的文件补认；`force` 不豁免提交硬门
- **空转与未产出报告**（`db5195268`）：worker 在探索中被打断、从未进入最终报告时，不再说成「写了 N 个坏 JSON」。消息改为「未产出最终报告」，建议缩小目标或抬预算

## 3. 安全与配置

- **审批 / 沙箱 / 授权档位从项目配置永久剥离**（`40830077a`）：`.rivet-config.json` 里的 `agent.approval`、`agent.unsandboxed`、`agent.permissions` 授信之后也不再生效。合法来源只剩内置默认、用户全局配置、profile、CLI flag、运行时切换。信任提示不再把这三项说成「授信能得到什么」
- **退役迁移不再制造悬空模型**（`89a21d6f2`）：`deepseek-v4-flash` 改指 `deepseek-flash` 之前，先把后继模型补进契约池。v3.28 上用户池被剪枝后，启动告警并静默回退到 `deepseek-v4-pro`（价位与视觉能力一起变）
- **非法 worker 档位不再打死整个应用**（`3cafeafca`）：`workers.patcherTier` 写成枚举外的值（如 profile 名 `cheap-flash`）时回落默认并写回，不再让 `loadConfig` 整份失败、更新后打不开

## 4. 模型通道与 worker

- **DSML 工具调用兜底**（`9387c963d`）：部分 DeepSeek 系中转把 `tool_calls` 写成 DSML 标记塞进正文。旧 JSON 兜底只认 `{`/`[`，这些调用整轮蒸发，会话看起来频繁中断。现识别完整 invoke、剥壳后仍保留周围散文
- **剥离内联 `</think>`**（`282355ac7`）：中转把推理结束标签留在 content 里时，不再当正文落盘。不碰 Anthropic 出站自造的 `<thinking>`
- **只思考、没有正文时仍可恢复**（`3b82e5133`）：轮次预算为不限时，思考重试不再被当成「已经到顶」而跳过；取消和共享重试预算仍然生效
- **空回复标成未完成**（`c3b47271b`）：模型没返回有效答案时记 `no-answer`，提示发送「继续」。不改已有缓存历史
- **worker 收敛成为通用规则**（`221ca96a9`、`a40ba7cb9`）：连续 3 次工具调用没有新信息就停，覆盖全部 profile（此前 20 个里 18 个没有这条，verifier 会空转到预算耗尽）。机制层对「换着花样的空结果」计数，出错不算空转

## 5. 星域

- **启明改为并肩推进**（`826f402ca`）：去掉「照路不代走 / 交还建设者」旁观框架。能自己判断的不问；只在方向变了、动作不可逆、或真互斥时提问
- **Theta 混合策略**（`7a533add9`，随后编译修复 `efa2d311c`、`16f27012c`）：检查从只读消费者改为优先读共享缓存、必要时经闸门真跑。缓存 8→16。连续 3 次 `no-fresh-verdict` 或会话接近上限时触发。目标是把「没有新结论」从 99%+ 降下来，超时率仍守住
- **星河拒绝丢维策略**（`5ad112035`，issue #368）：`weighted_confidence`、`first_success`、`majority` 只会留下一条结果，和多维分析不相容，调用时直接拒绝并建议改用 `all_required` / `primary_decides` / `quorum`

## 升级注意

- **项目配置里的审批、沙箱豁免、权限规则不再生效**，授信也一样。写在 `.rivet-config.json` 的 `agent.approval` / `agent.unsandboxed` / `agent.permissions` 会被剥掉。要关审批或开沙箱，改用户全局配置、profile 或运行时开关
- **多会话写同一文件**：对方进程已退出，或独占认领超过 10 分钟没再改且该文件工作区干净，会自动接管并在工具结果里说明。对方还在写、或文件上仍有未提交改动，会问你要不要接管
- **非 git 目录交付是 YELLOW**：文件改动还在，只是无法按归属提交。不要把它读成「没有改动」
- **全量测试被别人的改动染红时**，交付门对无法归因的失败给 YELLOW。自己改出来的回归仍然 RED。不要为了转绿去重跑整仓 `run_tests`
- **技能改动从下一个新会话生效**。当前会话继续用钉死的那一版正文和资源
- **看图 / 画图**：指定看图模型从下一个新对话生效；画图保存后当前对话的工具表会刷新
- **`deepseek-flash` 悬空引用**：若 v3.28 启动时把默认模型退回了 `deepseek-v4-pro`，本版会把 `deepseek-flash` 补进模型池后再迁移。请核对设置里的默认模型是不是你要的价位
- **Windows**：新包的 sidecar 进程名是 `tianshu-runtime.exe`。从旧包升级时，若新名不可用会回退 `node.exe`
- **Linux 渲染与无硬链接锁在本版 AppImage 里**。3.28.0 的 AppImage 没有这套开关。打包之后的两笔信任门修复不在本版安装包内
- **星河**：多维分析不要再选 `weighted_confidence` / `first_success` / `majority`，这三档会被拒绝

## 13. 打包之后的信任门补漏

这两笔在安装包打完之后才进 main，源码同步会带上，已打出的 macOS / Windows / Linux 包不含。

- **未授信项目的读注入面收口**（`f7d47ab8e`）：skills、rules、commands、memory、playbook、presence、plans、agents 未授信一律不读不注入。另收了 Windows 会话信息 ACL、私有 IP 判断失败时拒绝、`/health` 精确匹配、插件入口真实路径
- **斜杠技能的第二入口**（`2667803f6`）：`/skill <name>` 和裸名 `/<name>` 此前绕过信任门，未授信仓库的技能正文仍能进用户消息。现三处装载都过同一道门
