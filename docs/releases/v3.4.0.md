## 1. TUI 交互五连修（公开仓 PR #40 / #41 / #42 / #43 / #45，作者 yq04）

- **排队消息语义对齐（#40，`b88375c06` + `02cd6413a`）**：AI 输出期间排队的普通消息不再在工具边界被自动注入（此前界面显示「⏳ 已排队」实际已发出，对齐 kimi-cli / codex 的 turn 结束后处理共识）——run 自然结束回填输入框，由用户再次 Enter 确认发送；守护中断（watchdog/convergence）自动续跑不回填。顺带输入框成为 live region 最后一行（滚动到底贴屏幕底部，Claude Code 风格）。
- **命令面板换绑 Ctrl+P（#41，`81d16bc34`）**：原 Ctrl+Esc 三条送达路径全断（Windows 宿主被开始菜单抢占 / 传统转义序列与单独 Esc 同码 / kitty 增强键盘 `27;5u` 未映射）——Ctrl+P（0x10）所有终端可靠送达，toggle 开关语义；翻历史入口不受影响（↑/↓、Ctrl+N、Ctrl+R）。键位文档全链同步（/help、首屏 tips、README 中英文）。
- **Ctrl+C 退出确认窗口可取消（#42，`e7c40c510`）**：确认窗口内 Esc / 任意编辑键 / 粘贴都取消退出、恢复输入框——修复幽灵输入（文字进 value 但输入框被隐藏）、带输入误退出、Esc 取消污染双击 rewind 计时四个缺陷；渲染防御兜底一切漏网路径。
- **跨 run 陈旧 todo 清单不复活（#43，`5b5c08ab7`）**：「◇ 任务 (5/5) 不更新」根因是上一轮全完成清单在新 run 开始后重新挂载，直到 AI 首次写 todo 才变化——`todosWrittenThisRun` 生命周期标志 gate 主区面板 + 侧栏 + GlanceBar 徽章；部分完成清单与守护中断续跑不受影响。
- **slash 提示分层（#45，`e2627d20c`）**：65+ 条命令全量按定义序展示对普通用户是噪音墙——空 query（输入恰好 `/`）只展示核心层（21 条高频标注 `tier: 'core'`），继续输入任意字符即过滤全量，Ctrl+P 面板永远全量；footer 引导「核心 N/M · 输入即过滤全部」。顺带补进有完整实现但从未进提示列表的 `/undo`（检查点回滚）与 `/resume`（会话选择器）。

## 2. 桌面端滚动与通知（dev 仓 PR#5 + 公开仓 issue #44）

- **底部微滚动意图保留（PR#5，作者 HarriethWiKk，`05d0321e6`）**：会话在底部时单格微上滚（gap 仍 ≤8px 落在 near-bottom 判定内）不再被持久钉底立即拉回——near-bottom 分支复用既有 400ms 用户滚动冷却窗，窗内不清 intent、不触发 `pinToBottomPersistent` 首拍回写、不转回 Following。v3.3.0 触底难根修（`899e775f`）的正交补充。
- **toast 通知 WebView2 残影（issue #44，`328221833`）**：Win11 弹窗一开一关后右上角出现「N/M 个子代理受阻 查看」半截错位残影且不自动消失——根因是 sonner 通知容器内联在带裁切的 `.shell` 树里、居中依赖 `transform: translateX(-50%)` 且挂着常驻 transform 过渡（脆弱的 fixed 合成层），弹窗开合时 Base UI scroll-lock 翻转 body 内联样式触发整文档重排后 WebView2 偶发按未平移位置绘制。修复：`ToastHost` portal 到 `document.body` + 无 transform 盒模型居中，主窗口与 popout 弹出窗口统一走新挂载入口，4 条回归契约防回潮。
