## 1. Starflow 星流迭代四升级 —— 从「能跑完全流程」到「跑得起迭代」

首战后复盘（`.rivet/knowledge/starflow-retro-2026-08-03.md`）直接催生了四项机制升级，全部落地：

**A. 席位选择自由度**：`starflow` 新增 `seats` 参数（与 `council_convene` 同构），首轮与复议轮双透传。修订重提时只召回「上轮否决的席位 + 相关域席」，不再默认全量评审——成本立降，否决拦截力不减。

**B. 增量评审**：`draftItems` 支持 `revision` / `previousVerdict` 标记。前轮已通过且未变的条目在评审渲染中标注「沿用前轮通过结论」，council 零改动（渲染文案即契约）。守卫：`revision` 与 `previousVerdict` 同现视为已修订重新评审——宁重审不放过。

**C. 基线预检**：首轮 council 评审前自动注入工作树现状块（目标文件 git status 命中行 + 最近 5 条提交 + 必答句）。「已合入/已在工作树」类否决从第 2-3 轮提前到第 1 轮，不再白烧席位。非 git 环境降级不阻塞。

**D. blocked 归属**：team 波次有 worker 未过时，报告追加工作树归属段——git status 过滤本波次 changedFiles；共享 worktree 无 diff artifact 时降级全量列出并标注「无法逐文件归属，勿整目录 add」。多会话共享工作区下，目录级命中显式标注「可能含其他会话改动」。消除「并发会话 vs 自己 worker」的认知迷雾。

### 配套修复

- `council` 席位 risk 缺 `mitigation` 字段击穿 `extractObligations`（starflow 点火阻塞根因）——入口规范化 + 消费端防御 + 席位 prompt 补 risk schema（治本）
- `quotePath=false`：中文/非 ASCII 路径在归属段与预检块不再漏报

## 2. 协作执行可靠性 —— 全局并发闸与它的审查修复

P1-6/7/8 落地了**全局 worker 并发信号量**（`agent.maxWorkers` 或 `RIVET_MAX_WORKERS`，默认 3，顶层 delegate/batch/background 统一入闸）、abortSignal 显式参数化（per-wave mailbox，不再读写共享实例状态）、写工 scope 强制与跨波文件冲突检测。随后经审查修复了四个真缺陷：

- **嵌套委派自死锁**：planner 持槽等子工、子工再等槽——嵌套委派（depth ≥ 2）豁免全局信号量，`RIVET_MAX_WORKERS=1` 时 planner 派发不再必死
- **跨波冲突 TOCTOU**：检查-登记移到同一同步块，同 tick 两个同文件写工不再双双绕过
- **僵尸唤醒**：等槽期间响应 parentSignal，abort 即出队 reject；`delegate_task` 主路径 signal 透传（此前闭包丢弃，abort 守卫是死代码）
- **闸口径**：verifier 空 scope 跑全量测试豁免；objective-gate 越界判定豁免测试文件；galaxy 文件全被夺走的写维度显式跳过并入报告

## 3. 审查契约全量改造 —— polarity 极性 + verdict ≠ status

修复「审查 verdict 被当成 worker 失败」的系统性失真（一晚三连败误升级事故）：

- `ReviewFinding` 新增 `polarity: defect | confirmation`——blocking 判定只认缺陷；确认性结论（已读码确认/链路闭合）进「已核实清单」，不再被标 CRITICAL blocking
- `normalizeReviewVerdictStatus`：审查/验证工单的结论性 failed/escalated（有 findings 且无基础设施失败标记）归一为 passed——连败计数、熔断、升级只记真实运行失败，审查 findings 不再被丢弃
- 审查指令补 severity/polarity/status 三语义契约；verified 文案带「N 项核实确认」

**Worker 契约补强**：summary 扩写验收加 status 门禁（passed 结果不再被失败扩展轮翻盘）；worker P0 热修包（契约/存活/并发四修 + 死循环实证回归锁）。

## 4. 桌面端 —— 新建会话去弹窗化 + 公开版上线体验

**新建会话去弹窗化（Codex 心智）**：默认路径零提问——欢迎页输入即创建并进入会话；侧栏 +、⌘N、命令面板等全部入口改道欢迎页并自动聚焦。不预创建空会话，发送才落记录。原弹窗完整保留为「高级新建」（命令面板/侧栏 caret/欢迎页文字链），cwd/repo、自治档位、隔离 Worktree、标题全部可达。

**模型选择器接真实数据**：只列已配 key 的 provider 下的模型（视觉模型除外），首档「跟随项目/全局默认」。选中新会话即生效，替代了与 provider presets 不对齐的演示数据。模型「擅长场景」description 数据链路贯通（schema → serve → ModelPicker），存量配置自动回填。

**公开版 + Pro 体验**：i18n 英文化（欢迎页/更新弹窗/发版日志 en 分支）、ProBadge 组件 + Pro 入口预拦截（isTauri 三态门控 + 升级对话框）、surface 可发现性（MORE_NAV）、Mission 中控台接线（档案 + 事件冷热分层折叠）、星域图谱去线程依赖。

**更新流程重设计**：发现 → 查看 → 下载渐进式；删 UpdateBanner 死代码，semver 对齐修复误报。

**细节**：新建会话乐观写入缓存消除欢迎页闪烁；粘贴/拖文件后中文输入法组词不再被打断；Windows 完全访问覆盖全部盘符；`harvest_shell_env` 超时放宽（login shell 慢不再误杀 env key）。

## 6. 授权与安全

**工作区外授权闭环**：`/grant` 斜杠命令 + 审批「批准并记住此目录」+ path-grants revoke/list + 桌面设置页；CLI `allow-dir/revoke-dir/list-dirs` 子命令。yolo auto-grant 持久化到 per-workspace store（跨会话存活）；yolo 模式下 `request_path_access` 不再无条件弹审批，文件工具自动升级 read→write grant。

**Windows 防护对齐**：driver 补齐危险脚本拦截（Invoke-Expression 防护与 macOS 对齐，共享 danger-guard）；`RIVET_NO_SYSTEM_PROXY=1` 可禁用 OS 系统代理回退（CI/沙箱/显式绕过）。

## 7. 证据防火墙 Phase 2 —— deliver 硬门禁

引用未经独立核验的 scout/worker 断言进交付文本时，从软提醒升级为门禁：`agent.scoutEvidenceFirewall = true` 或 `RIVET_SCOUT_FIREWALL=1` 开启 commit 硬拦（默认 opt-in 关）；报告轮警示恒开。claim tracker 全链路接线（hook 回调 + verifiedAt 核验标记），`[待核]` 标注是诚实降级的出路。

**cancel-rest 短路**：`first_success`/`quorum` 聚合策略中途达标即取消剩余兄弟 worker，省 token 和墙钟（`RIVET_CANCEL_REST=0` 可关）；写工永不被 policy-cancel（不留半改文件）。
