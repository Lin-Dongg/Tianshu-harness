# v3.1.2 发布记录

> 2026-08-10 · 补丁版本：启动资源误报修复 · write_file 指针机制停用 · append 分块写（3 commits）

## 1. 可靠性门禁误报修复（刚进会话不再误降级）

- **启动冷爬升不再误报内存压力**：资源趋势回归窗口排除启动冷却期（默认前 3 个样本）的 RSS 爬升段。此前新会话第 2 轮即把正常启动爬升（实测 249MB/样本，阈值 67MB）判为内存泄漏并进入 degraded 模式，拦截写操作
- **`2>/dev/null` 不再误判为写命令**：bash 写副作用检测先剥离 `/dev/null` 无操作重定向——degraded 模式下纯只读的 `grep … 2>/dev/null` 不再被拦

## 2. write_file 指针机制停用（worker 写文件刷屏报错治理）

- **历史指针停产**：大内容 write_file 的调用参数不再被替换为 `[file written to …]` 显示指针——worker 模型会把历史指针当格式模仿、回吐为正文（实测单批 galaxy 会话 21 次拦截、单 worker 空转 370 万 token），省的 token 不抵行为代价。完整内容保留在历史中，上下文压力由既有 compaction 承接
- **存量指针仍受保护**：pointer-guard 与幂等化解保留，旧会话历史里的指针回吐依旧可被识别拦截
- **纠偏提醒必达**：pointer 纠偏 system-reminder 改走 functional 通道——此前 discipline 通道每轮限 1 条、被其他提醒抢占后静默丢弃（8 次犯规 0 条落地）
- **新文件语法回滚修复**：新写入文件语法 fatal 时直接移除该文件（此前无备份可恢复，报"自动回滚失败"并把坏文件留在磁盘上）

## 3. write_file append 分块写

- 新增 `mode: 'overwrite' | 'append'`（缺省 overwrite）：append 原样追加、不自动加换行、文件不存在则创建
- 大文件推荐分块写：先 overwrite 首块，再 append 依次续块；append 跳过盲覆盖守卫与整文件语法回滚，不触发重写循环提示

## 4. 兼容性

- 补丁版本，无破坏性变更；桌面端本次不随发，sidecar 沿用 3.1.1
