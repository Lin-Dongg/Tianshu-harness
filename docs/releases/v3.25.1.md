## 一、CLI：进程内开新会话 `/new`

会话进行到一半想清空上下文继续同一个工作区，此前只能重开进程。现在 `/new` 在**不重启进程**的前提下开一段新会话：当前会话正常收进历史（可从会话列表找回），新会话继承同一工作区与配置，上下文从零开始。

配套的重置逻辑落在新模块 `src/tui/new-session.ts`（`slash-commands.ts` 相应减重）。

## 二、自动化面板：写盘与保存的失败不再静默（issue #266 四波）

自动化任务「保存了但其实没保存」是这一轮的主要修复对象，四波依次收口：

- **W2 · 保存失败可见化** — 保存错误经错误映射落到表单内的常驻错误块，不再只在几秒后自毁的 toast 里一闪而过；用户能对着错误定位到具体字段。
- **W3 · 运行时能力自证** — 老 sidecar 不支持 `PATCH` 时，桌面端**先关掉编辑入口并说明原因**，而不是让用户编辑完才发现保存无门。
- **W4 · 写盘失败不再静默** — 调度表写盘的结果以 `PersistOutcome` 回执透出，界面按「内存已改、重启后会丢」的真实语义分三态显示（**不把可恢复的权限问题说成「保存失败」**，避免用户重打一遍）。
- 编辑态显名 + 保存入口由 `dirty` 驱动（没改动就不亮）。

## 三、读取与上下文内核：read_file 链路重做

模型「以为读了文件、其实只拿到骨架」的一族问题集中收口：

- **大文件读不再剥正文** — 正文页优先于折叠骨架，模型拿到的是连续内容而不是结构大纲。
- **PARTIAL 门与硬门改由读预算决定** — 消除 80/100KB 静态门与窗口 cap 的「双重真相」。
- **日志类豁免硬门** — 超限日志给有界 head/tail preview，取代此前直接 `File too large` 拒绝；`reject` 判定前移。
- **内存裁顶 50K→120K、read_file 预算 20K/30K→40K/60K token** — 让已授予的 read cap 真正到达模型（此前 cap 给了 120K，内存层又在 50K 处砍一刀）。
- **上下文压力截断分档** — 70–90% 保留 200 行预览，仅 ≥90% 才砍到 30 行（原先 70% 起就一律砍 30 行，1M 窗口下等于无压力也把工作文件收走）。
- **模型可见相对路径统一正斜杠** — 修 Windows 下 neighbor-hint 的反斜杠失败。
- **落盘上限与内存上限对齐** — 单条工具结果的落盘上限提高到能容下内存侧允许的 120K，会话恢复/重放不再拿到被二次削小的历史。
- **不可达的 `File too large` 兜底移除** — 探针实测 150 用例 0 命中后删除，注释同步诚实化。

结构上：`applyFoldThenPartial` 迁至 `truncation.ts`、工具结果摘要拆出 `tool-summary.ts`、cron 计算拆出 `cron-tick.ts`、`openai-client` 拆出 `error-hints.ts`——四处都是沿接缝拆出，让点名巨石回到行数 ceiling 以内。

## 四、桌面端：侧栏运行态、个人中心、手机端

- **侧栏运行态可见性补完** — 预览行标识、项目行汇总、截断放行、待审批标记；随后补齐置顶段汇总、项目徽标口径、整组放开两档；侧栏会话行尾新增「运行中」环（形态代色、3s/圈、不占最左槽位）。
- **顶部「任务进行中」条**扫光改呼吸 + 冷却，消除余光干扰。
- **切换工作区后对话上栏项目名跟随当前会话**；排队卡字号层级收成两档并加动作组分隔、分页条动作降一档（issue #264 同型点全仓扫描所得）。
- **个人中心与创始铭牌** — Wave 1 数据面（头像与创始铭牌落 sidecar）、Wave 2/3 卡片与铭牌组件、Wave 5 审查发现的铭牌守卫与位次分母修复。

## 五、推理复读守卫（issue #260 / #167）

模型思考退化成复读短句时，此前只有「拦」与「不拦」两种结局：

- **阈值放宽** — 把「卡死」（长时间原地重复）与「口头禅」（偶发短语重复）分开判定，后者不再被误拦。
- **先纠正再中止** — 命中复读时先**纠正重试一次**（丢掉那段退化推理、尾部附纠正指令；绝不回放，回放会强化循环），第二次仍命中才冒泡成终态错误。

## 六、工程与发版

- **测试运行器**：批次按进程组收场 + hang fixture 自毁上限——堵住 21 个孤儿进程泄漏。
- **公开仓 sync**：不再覆盖目标仓 `CREDITS.md` 台账（曾每轮重放 142 笔 credit 提交）；credit 自动落账停用后回退（曾撑出 719 笔人造提交，公开仓历史已重写 1047→329）。
- **桌面端启动**：关闭混淆的 base64 字符串编码——它让 sidecar 冷启动从 ~1s 恶化到 ~35–42s，而 Rust 侧只等 15s，导致 3.23.0 起每个桌面包冷启动必然被判失败。
- **Windows 打包**：WiX 品牌图字段名订正（`bannerImage/dialogImage` → `bannerPath/dialogImagePath`，当前值阻断打包）。

## 已知问题

- **Windows 杀毒软件误拦/误杀族**（安装被拦 / 主防误杀 / 会话内 443 不通三类现象，成因与处置各不相同）——**v3.25.0 的 Windows 产物因 minisign 验签失败已从更新源撤下，本版待重打后恢复**；签名管线已落地但证书采购与厂商白名单仍在进行中。完整档案：`docs/known-issues/2026-09-23-windows-antivirus-interception.md`；用户侧处置：`docs/guides/troubleshooting.md` 第 11 节。
- **macOS 首次打开报「已损坏」** — 仍为 ad-hoc 签名、未经 Apple 公证（Developer ID 证书未就位）。安装后执行一次 `xattr -cr /Applications/Tianshu.app` 即可；应用内自动更新不受影响。
- **MiniMax-M3 视觉上游故障（延续）** — 上游对 M3 图片请求返回 500（纯文本正常），识图建议 glm-4v-flash / deepseek-flash。
- **手机遥控为局域网设计** — 无 HTTPS，令牌是 LAN 唯一凭证；公网请走 Tailscale / SSH 隧道，不要直接端口映射。
- **本版更新源仅含 macOS 两个架构** — `latest.json` 当前只列 `darwin-aarch64` 与 `darwin-x86_64`；Windows 条目待产物重打并验签通过后补回。

## 升级注意

- **本版是「两版合体」**：从 v3.24.0 直接升上来的用户，更新内容请对照本记录 + `docs/releases/v3.25.0.md`。
