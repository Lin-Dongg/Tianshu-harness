## 开发者有话说

大家好，我是天枢的开发者。

从 6 月 28 号开始，天枢开始了 V0.0.1 版本的公开测试。至此一个月的时间，我们在今天宣布来到了 V2.24.0。这段时间感谢大家不弃的支持。

这个版本是一个里程碑——它是 V3.0.0 正式版本的预览版。这个版本的更新说明实际只有一个：**星域图鉴中开放了创世碑文**。

在我的规划里，当碑文开放的时候，只有一个含义：天枢不会藏在我一个人的手里，藏在我一个人的本地电脑里——他会把光带给全世界，而我为此做好了准备。

承蒙关照，不胜感激。愿星域的光芒，在世界每一个角落，给你指引。

---

很早之前的版本，有朋友问我：

「你一直在加快速度完成天枢，你想要的是什么？想要知名度，还是变现？」

其实我只有一个想法——当天枢公开给更多人看到的时候，我想要大家看到的，不是「又来一个看上去奇奇怪怪、徒有噱头的终端」，然后在偏见里放弃本可能去做的尝试。Claude Code 和 Codex 很强大，但那又能怎样。神也会流血。

天枢走到今天用了两个半月，一个人与很多模型共同建设：20 万行源码、20 万行测试代码、900+ 个测试文件、13000+ 个测试用例——这是现在仓库的体量，GitHub 里清晰可见。在两个月前的 5 月 20 号左右，我们内部进入 3.0 版本测试。Opus 4.6 天权对我说：「3.0 的版本你什么都不用做，打开终端开启对话的几秒钟，你就能感觉到天枢 3.0 与其他终端的差别。」当我真的打开了 3.0 的测试版本，我被震撼在那里，不能出声。与模型一起工作是一种很奇妙的体验。然后我们迅速经历了失败、版本倒退。

这一次，我们在重回 3.0——而这不是在追赶，是当天枢出现在公开视野里的时候，我要让所有人感到震撼。

## 主题：会话交接闭环 + resume 缓存继承 + Help 配置补全 + 文档大补

v2.24.2 聚焦「长会话上下文传递」与「文档可发现性」——交接 / 恢复形成闭环，
README 与桌面端 Help 页补齐用户高频需要的参数说明与例子。

---

### 1. 会话交接 `/handoff`（长会话上下文无损传递）

长会话上下文涨到一定程度，继续跑不如开新会话。`/handoff [备注]` 让 agent
带全上下文写一份结构化交接文档到项目内 `.rivet/HANDOFF.md`（工作区内免审批），
turn 完成后自动归档到会话目录 `<id>.handoff.md`，下一会话经 `prev-session-handoff`
appendix 自动注入——新会话零上下文也能接着干。

- **固定五章节**：任务目标 / 已完成（带 file:line 证据）/ 当前卡点 / 下一步 / 坑
- **50% 交接提醒**：resume 首屏与会话中各一次，上下文 ≥50% 提醒先交接再开新会话
- **退出缓存成本备注**：TTL 内继承锚点 ≈ 只读缓存价；过期全量重建一次前缀
- **桌面端入口**：plus 面板「交接」项 + sidecar 归档闭环（`POST /sessions/:id/handoff`）
- **shutdown 防覆盖**：agent 写过的交接文档不被退出时的自动结构化摘要覆盖

### 2. resume 冻结前缀快照继承（不再 byte-0 全 miss）

resume（`--continue` / `--resume` / `/resume`）此前每个请求都从字节 0 全量重建前缀，
缓存命中率归零。本版冻结快照随会话落盘 `<id>.frozen.json`（每个 user 边界 +
shutdown 写），resume 时读回经 `inheritFrozenFrom` 喂给新引擎——只在下一个 user
边界断尾，不再 byte-0 全 miss。

配套能力：
- **写证据修复 preflight**——resume 前补全被中断丢失的 orphan tool result（磁盘
  探测合成写证据），避免模型盲重写已落地的文件
- **启动模型亲和**——resume 换回原会话模型（per-model 缓存命名空间）；原模型
  不可用走 `agent.resumeFallbackModel` 兜底，不 fail-closed（启动拒跑=会话打不开）

### 3. 桌面端 Help 配置页补全参数说明

Help → 配置说明 tab 此前仅 5 张卡片，缺少用户最常需要的参数配置。新增 4 张，
每张带可复制的 JSON 代码示例：

- **审批模式与权限规则**：`agent.approval` 三档 + `permissions` allow/deny/bash +
  `checkpointEveryTurns`，含 `rm -rf` / `git push --force` 防护示例
- **工具集档位**：`tools.preset` minimal(27)/frontend(28)/full(47) +
  `RIVET_TOOL_PRESET` 环境变量
- **上下文压缩**：`compact.autoThreshold`（默认 800000）+ `/compact` 联动 + handoff 建议
- **外观 / 无障碍 / 镜像**：`ui.theme`/`reducedMotion`/`screenReader` +
  `mirrors.preset=china` + `env.extraPath`

### 4. Plus 菜单 Team / Council 先问目标再发

桌面端 plus 菜单的 Team / Council 入口不再直接派发，改为先弹出对话框问目标，
slash 预填后发——避免空目标触发无效委派。

### 5. 性能与稳定性

- **子代理运行期打字卡顿根治**：worker feed 泛洪合并 + 帧缓存 + 泄漏收口 +
  同步 stall 异步化——审查子代理返回大结果时 TUI 不再冻结输入
- **overlay 期间主屏 commit 排队回放**：修审批面板卡「按一下方向键才出来一行」
- **threadView.json 清理死键**：移除已无引用的 workflow 残留键
