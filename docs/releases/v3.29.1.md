## 1. 安全与信任门

- **recall 不再读仓库自带的 commit 事实**（`43a642fc1`）：recall 在 query 含 7–40 位 hex 时自动读取 `.rivet/knowledge/commit-facts.jsonl`，此前无任何信任门——未授信项目预置该文件即可注入模型上下文（端到端复现确认）。门按审计原则下沉到读取函数内部；存在性探测名单补上该文件；清单式 surface 测试登记该通道
- **桌面授信提示同步 stakes**（`8793b74b0`）：纯技能/规则仓库在桌面端不弹授信提示、技能静默不装载、唯一解释在用户不可见的 sidecar 日志。触发条件对齐 CLI 内核判据（敏感键 | hooks | skills | rules）；弹窗如实告知「安全档位键授信与否都不生效」，不再把审批/权限说成「授信能得到什么」
- **/skill 按技能来源判门**（`851fbacd2`）：未授信项目里你自己的 `~/.rivet/skills` 与内置技能恢复可用（此前一刀切全挡，可用性误伤）；项目槽位技能未授信仍不展开，冻结快照撤信的窄例仍被门住

## 2. 交付门与验证

- **识别 dotnet / maven / gradle 验证命令**（`12657e363`、`2f87c2df2`、`159f8a2e0`，issue #380）：含 clean 前缀、全局选项、`.bat`、管道形态；`--filter` / `-Dtest=` / `--tests` 降级 unknown 不夸大全量。修复合入晚于 v3.29.0 打包，本版才出厂
- **反应堆选择器与 goal:task 形态**（`574efc885`）：`mvn -pl / -rf / -am`、`-DskipTests` / `-DskipITs` 等子集跑降级 unknown，多模块仓的局部测试不再被记成全量证据；`./gradlew :app:test`、`mvn surefire:test` 等目标词在 `:` 后的高频形态入账
- **会话中途 git init 不再被永久阻断**（`99537a543`）：提交硬门触发时现场重采一次基线，仓库现在可用即放行（容忍首次提交前的 unborn HEAD；台账有证据的会话文件不会被重采吞成外部文件）。「无法归因不提交」的默认不变。另修 CLI 侧门：同步采集此前不查 git 退出码，硬门对 CLI 整体失效，两端口径已对齐
- **先验后写的越界写入不再作废验证**（`2a78388b9`）：跑完验证往 `/tmp` 写个 fixture 曾把既往全部验证 sticky 判 stale（v3.29.0 只修了「先写后验」顺序）；两个顺序现已同根收口
- **全量失败的 YELLOW 降级要求证据**（`0461ef384`）：此前任何全量失败恒为「未归因」自动降级——单会话自己改坏 impacted test 也搭便车成 YELLOW。现需确有外部在途改动或隔离单跑配对，无证据保持 RED 并指引取证出路
- **敏感路径判据改词元级**（`c293ab45b`）：`src/tokenizer.ts`、`secretary.ts`、`.environment.ts` 等 29 个正常文件曾被判敏感 → 指纹不可用 → 作废全部验证；收窄后零误伤，必拦的凭据形态（.env 家族 / credentials.* / 私钥 / token、secret 词元）全部保持 fail-closed
- **L4 指引落地**（`0e02e7e08`）：stale 丢弃 N 条且确有越界路径时，交付报告点名路径并指引「移入仓库内后重跑验证」，替代误导的 "no tests were run"；stale 计数注释对齐实现（仓内再编辑是良性多数）
- **typecheck 锁超龄接管补上回归**（`a5ca5b646`）：该修复此前回退后 52 个用例无一变红（零测试）；另 release 前校验锁主 pid+startedAt，防被超龄接管后旧持有者误删新锁

## 3. 多会话文件租约

- **接管改 CAS 释放**（`95542f17f`）：判定 → 释放之间对方合法刷新凭据（自己写前认领或写后入账）时，不再按陈旧结论删行——「双方各持锁并发写同一文件」的窗口关闭；失配落回「问」，自动与显式（审批等待，分钟级窗口）两条路径同修
- **被忽略文件不再被当成「干净」**（`4de32f23b`）：`.env`、`.rivet/plans/*` 等 git ignored 文件上对方的未入库内容，此前恒判干净、被自动接管无声覆盖且无 checkpoint 兜底；现落「问」。Windows 反斜杠认领键形的同款失效一并修复
- **探针惰性化**（`d640648a5`）：死持有方回收与「仍新鲜」分支不再白等一次 `git status`（挂起时最坏 13 秒）；全仓认领键（ast_edit 缺省）直接落「问」，不做全仓扫描；自动接管注记写明「对方工作区里还留着什么」（脏态三分支）
- **认领冲突的审批卡说人话**（`fb3bb0c8a`）：TUI 审批卡渲染「⚠ 认领冲突：文件正被另一个会话持有」+ 陈旧判据 +「批准 = 接管该文件」；此前只是一次普通 write 审批，用户不知道自己在授权接管。sidecar 事件已带结构化字段，桌面端文案随后续版本落地

## 升级注意

- **全量测试失败时的黄灯收紧**：没有外部在途改动证据的全量失败保持红灯。自己改坏的测试被染红时，按报告指引做隔离单跑配对取证，不要为了转绿重跑整仓
- **非 git 目录的交付**：会话中途 `git init` 后可直接交付（硬门现场重采基线）；仍不是 git 仓库则照旧无法提交，文件改动本身不受影响
- **多会话接管更保守**：被忽略文件（`.env`、`.rivet/plans` 等）上的接管一律先问；判定之后对方又写了文件时，接管自动放弃重新问
- **未授信项目**：recall 不再返回仓库自带的 commit 事实（授信后恢复）；你自己的全局技能与内置技能恢复可用
- **桌面端**：`~/.rivet` 不要做成符号链接 / junction（serve 会拒绝启动，POSIX 每次启动还会 chmod 700）；扫码配对只在独立 TLS 服务（`rivet serve --tls-*`）下可用，桌面内嵌 sidecar 不提供二维码
- **发布目录（release-catalog）已写入 3.29.0 条目**，服务端启用后桌面更新会按目录选源并对下载包独立校验 SHA-256
